# PySpark Item Sales Data Processing (로컬 유닛 테스트 환경)

이 프로젝트는 PySpark를 활용한 데이터 처리 파이프라인 예제이며, 주된 목표는 **실제 서버 환경(Kafka, RDB)에 의존하지 않고 로컬에서 간단한 샘플 데이터로 유닛 테스트를 수행**할 수 있는 구조를 마련하는 것입니다.

## 배경

일반적으로 스트리밍 데이터 처리 파이프라인은 다음과 같은 의존성이 있습니다.

- **Kafka**: 스트리밍 데이터 소스
- **RDB (예: PostgreSQL)**: 마스터 데이터 로드용
- **Spark Cluster**: 대규모 데이터 처리를 위한 클러스터 환경

하지만 개발 초기나 로컬 테스트 환경에서는 보안 문제, 네트워크 제한, 인프라 접근 제한 등의 이유로 실제 Kafka나 RDB에 접근하기 어려울 수 있습니다. 이 경우, 매번 해당 환경에 코드를 배포하고 테스트하는 것은 매우 비효율적입니다.

## 핵심 목표

- **의존성 제거**: Kafka나 RDB에 직접 연결할 필요 없이, 로컬 CSV 파일과 Spark의 local 모드를 사용하여 테스트합니다.
- **빠르고 가벼운 테스트**: 별도의 클러스터나 인프라에 의존하지 않고, 개발 머신에서 바로 결과를 확인할 수 있습니다.
- **로컬 샘플 데이터 기반 검증**: 실제 프로덕션 데이터 대신, 간단한 샘플 CSV 데이터를 통해 전체 파이프라인의 로직을 검증할 수 있습니다.
- **유닛 테스트를 위한 모듈화**: 비즈니스 로직(`process_item_sales_data`, `analyze_item_sales_data_statistics`)을 별도 함수로 분리하여 독립적인 유닛 테스트가 가능하도록 구조화했습니다.

## 주요 기능

- **process_item_sales_data**: 아이템 판매 데이터와 마스터 데이터를 조인하고, 환불 건 제거 및 총판매금액 계산 등의 전처리 수행
- **analyze_item_sales_data_statistics**: 윈도우 기반으로 판매 금액, 판매 수량 등 집계 통계 산출

이러한 모듈화된 구조 덕분에 테스트 코드(`tests` 디렉토리)에선 단순히 CSV 데이터프레임을 로드한 뒤 위 함수들을 호출하는 것만으로도 로컬에서 손쉽게 로직 검증이 가능합니다.
